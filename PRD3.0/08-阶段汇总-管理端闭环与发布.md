# 阶段汇总：管理端闭环与发布（2026-09-10）

> **用途：** 给组员 / 评审一眼看清本阶段做了什么、怎么用、已知边界。  
> **代码：** GitCode `main` @ `c93be4d`（及之后本地续修）。  
> **本地：** http://127.0.0.1:8000/ · 管理账号 `admin` / `Admin2026` · 改前端后 **Ctrl+F5**。

---

## 一句话

管理端收成「场景 / 病种 / 病例」三选一；**只有正式场景**可发布到学员端；测试场景可写草稿；场景改正式后草稿挂钩会自动重算，避免卡死发布。

---

## 本阶段交付

| 模块 | 结果 |
|------|------|
| **管理端入口** | 「病例与场景」拆成新建 hub + 场景 / 病种 / 病例分页，不堆在一页 |
| **场景档位** | `tier`: `test`（测试）/ `formal`（正式）；列表可「设为正式 / 改回测试」 |
| **发布策略** | 白名单场景 + `tier=formal` 可进学员端；测试不可发布 |
| **评分衔接** | 新正式场景可走评分回退（知情/随访包），审核页展示「和现有练习能不能接上」 |
| **草稿挂钩刷新** | 打开草稿 / 改场景档位时重算 `design_hooks`，解决「已改正式仍不能发」 |
| **病例材料** | 三路径：纯人写 / 粗糙材料 / ZIP；家属协同 × COPD 有独立样本 |
| **展示净化** | 病例参考区去掉 Markdown 脏字段；家属场景开场与角色提示更贴家庭沟通 |
| **文档** | PRD2.0 补充管理端/评分；PRD3.0 闭环材料与测试清单；样本说明见 `web/data/samples/README.md` |

---

## 关键流程（建议自测）

1. **场景** → 新建「家属协同沟通」类场景时先选**测试**或直接**正式**。  
2. **病种** → 如 COPD（若已有可跳过）。  
3. **病例** → 选正式场景 + 病种 → 用 `web/data/samples/` 下对应人写 / 粗糙 / ZIP 样本走完审核。  
4. 若当初是测试：在场景列表点**设为正式** → 回草稿箱点「继续」→ 核对挂钩全过 → **发布**。  
5. 学员端 `#practice` 选该病例对话，确认语气偏家属协同而非纯随访脚本。

## 已知边界

- **正式 ≠ 自有完整评分表**：新场景可能借用知情/随访评分包，审核页会提示回退。  
- **本地草稿库**在 `/data/`（不入库）；换机器或清库后草稿需重做。  
- **密钥**：`.env` 中 `AGNES_API_KEY` 等勿提交；无密钥时对话/评分能力受限。  
- 临时诊断脚本（`scripts/_chk*.py` 等）、个人简历默认不进仓库。
