# 管理端 · 三选一新建（PRD 3.0）

> **状态：** 产品定稿 + 前端已按本文改版（2026-09-10）。  
> **一句话：** 老师打开「病例与场景」，先选 **要建哪一种**；三种互斥，各占一页，不要在同一屏塞场景表单 + 病例材料 + 形象。

---

## 一、问题

PRD2.0 管理端把「训练场景」和「添加病例」拆成两个子页签，老师容易迷路：

- 加病例页里又选场景，场景页里又能加人又能手搓场景；
- 「关卡 / 对手」话术混进管理端，和老师日常「病例 / 病人」说法不一致。

老师真正要做的通常只有一件：

1. **新开一种沟通局**（少见，进阶），或  
2. **新开一个试验病种目录**（如 COPD），或  
3. **新开一个试验/访视病例**（选场景 + 病种 + 材料）。

---

## 二、设计：固定两场景 + 三选一

### 2.1 固定可挂场景（默认）

| 对外名称 | `scene_key` | 评分表 |
|----------|-------------|--------|
| 知情同意 | `informed_consent` | `scoring-rubric.json` |
| 随访（询问） | `follow_up` | `scoring-rubric-followup.json` |

列表只作说明；**不必**为了加病例再去「训练场景」页。

### 2.2 三选一（一次只进一条）

| 入口 | 一句话 | 独立页做什么 | 不做什么 |
|------|--------|--------------|----------|
| **新增场景** | 新开一种沟通局 | 填名称/简码/说明 → 保存场景条目；页顶只读展示本期两场景 | 不写病例材料、不绑形象 |
| **新增病种** | 扩试验病种目录 | 填名称/编码/ICD → 写入病种列表，供加病例下拉 | 不写病例材料；评分 overlay 可后配 |
| **新增病例** | 新开试验/访视病例包 | 选场景 → 选病种 → 材料三路径 → 人审发布 | 不在本页创建场景/病种目录 |

> **三选一 ≠ 三步都要走。** 按手头任务点一个即可；建议顺序：场景（若需要）→ 病种 → 病例。草稿箱 / 已发布 / 数字人形象仍是旁路页签。

### 2.3 信息架构（子页签）

```
病例与场景
├── 新建          ← 默认；三选一 hub 或某一独立页
├── 草稿箱
├── 已发布
└── 数字人形象    ← 次要；不进新建主路径
```

已去掉单独的「训练场景」子页签：固定两场景合进「新建」说明；新增场景走独立页。

### 2.4 页面原则

1. **一页一件事。** 新增场景/病种页只有各自表单；病例页只有选场景 + 病种 + 材料路径。  
2. **返回只回到新建 hub**，不跳进草稿或形象。  
3. **管理端文案**：场景 / 病种 / 病例；不用「关卡 / 对手 / 加一关」。

---

## 三、与材料三路径的关系

「新增病例」进入后，**材料从哪来**仍是 PRD2.0 §三路径（写大概 / 交材料 / 纯人写）→ 同一套人审页。  
PRD3.0 只改 **入口分流**；「新增病种」只扩目录，不走材料路径。

「新增病种」与评分：新病种可先入库，再按 [04](./04-场景与病种评分设计方案.md) 补 overlay；未配时用场景通用表。

---

## 四、非目标（本期 UI）

- 不在新建 hub 堆形象库、JSON 兜底（JSON 仍可藏在病例页工程折叠里）。  
- 本期「新增场景」页仍只建场景条目；**完整评分包克隆 / 病种 overlay** 以 [04-场景与病种评分设计方案.md](./04-场景与病种评分设计方案.md) 为准（引擎分期挂接）。  
- 学员端选人/熟练度逻辑不在本文范围。

---

## 五、验收口径（摘要）

详见 [02-测试清单.md](./02-测试清单.md)。

- 打开管理端「病例与场景」默认看到三选一，而不是「加一关对手」。  
- 点「新增场景 / 新增病种 / 新增病例」各自独立页；病种入口在病例前面。  
- 固定两场景在 hub / 病例页可见；不必再找「训练场景」页签。
