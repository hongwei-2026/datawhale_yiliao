# 情绪表达与语音交互（PRD 2.0）

> **怎么读：** 先讲小刘「听得出情绪吗」的故事 → 发现问题 → 再讲我们怎么设计。  
> **关键结论先说清：** 当前旁白是 **TTS 朗读生成好的文字**。TTS **做不到可靠的情绪演技**。  
> 情绪主要靠 **讲话内容 + 讲话方式（提示词）** 做出来；语音只是可选外壳。  
> 关联：[03-病人AI思考逻辑.md](./03-病人AI思考逻辑.md) · [01-场景设计.md](./01-场景设计.md) · [02-问题引擎与对话多样性.md](./02-问题引擎与对话多样性.md)

---

## 一、先讲故事：小刘以为「有语音就有情绪」

### 1.1 练习模式 · 文字已经「有情绪」

小刘跟李建国随访。  
他责备一句后，屏幕出现「受试者：有点抵触」，建国回：「我也不是故意的……记不太清。」——短、防备。  
他改口安抚，建国说：「那我说实话……去女儿家那天忘了。」——松口、可略展开。

**即使关掉喇叭**，小刘也能从 **用词、长短、是否肯说细节** 感到情绪在变。  
这是 [03](./03-病人AI思考逻辑.md) 思考引擎已经在做的事。

### 1.2 打开 TTS 之后

系统用 MiniMax 把建国的文字 **读出来**。  
小刘期待「抵触时声音发怒、放松时声音温柔」——结果往往是：

- 同一条音色、节奏差不多  
- 接口偶尔带 `emotion` 参数，效果弱或不稳定  
- 余额不足时直接失败，对话还能靠文字继续  

他才发现：**喇叭响 ≠ 情绪演技。**  
真正让人感到「建国急了 / 松了」的，还是 **他说了什么、怎么说的**。

### 1.3 王阿姨那一段

王阿姨：「您说得太快了，我跟不上……能不能再说一遍？」  
哪怕 TTS 用中性音读，学员也能感到：**她急、她跟不上**——因为 **句子结构和请求方式** 在表达情绪。

## 二、从故事里发现问题

| # | 现象 | 问题 |
|---|------|------|
| **E1** | 文字里已有抵触/放松，TTS 却听不出 | 不能把「情绪表达」押在 TTS 音色演技上 |
| **E2** | 关掉语音仍能练完 | 语音必须是 **可选增强**，主链路是文字对话 |
| **E3** | 情绪若只改「长短」 | 太窄；应体现在 **说法、披露、接话、语气词**（见 01 五维） |
| **E4** | 考核若也播心情标签 | 泄题；考核应弱化过程情绪提示 |

**设计命题：**  
在 **TTS 无法可靠演情绪** 的前提下，如何让学员 **稳定感到** SP 的情绪与状态变化？

**答案方向：**  
主攻 **生成文本的讲话方式（提示词）**；TTS 只负责把字读出来；演示可纯文字。

## 三、设计总览：情绪分三层，别混在一起

<img src="assets/prd2-emotion-three-layers.png" alt="情绪表达三层：状态层 / 表达层（主攻）/ 播报层（可选 TTS）" width="100%" />

```text
┌─────────────────────────────────────────────────────────┐
│ ① 状态层（已有）  trust / stance / disclosure_depth      │
│    → 决定「敢说多深、配不配合」                            │
├─────────────────────────────────────────────────────────┤
│ ② 表达层（主攻 · 提示词）  讲话方式 / 用词 / 句式 / 信息量 │
│    → 学员读文字就能感到情绪                               │
├─────────────────────────────────────────────────────────┤
│ ③ 播报层（可选 · TTS）  把文字读出来                       │
│    → 不保证情绪演技；失败则静音继续文字                    │
└─────────────────────────────────────────────────────────┘
```

| 层 | 解决什么 | 不解决什么 |
|----|----------|------------|
| 状态层 | P2 藏与松口（见 02、03） | 不直接等于「好听的声音」 |
| 表达层 | 让人 **读得出** 情绪 | 不依赖声线表演 |
| 播报层 | 听读便利、沉浸 | **不承担** 情绪设计的成败 |

## 四、表达层 · 具体怎么设计（提示词下功夫）

这是本文技术重点：**情绪写进「怎么说话」的指令里**，再生成文字。

### 4.1 每轮给模型的「讲话方式」包

在 `patient_engine` → `speak_style` 基础上，扩成可讲清的 **表达包**（设计规格）：

| stance | 讲话方式（写进 prompt 的倾向） | 学员读到的感觉 |
|--------|-------------------------------|----------------|
| 愿意配合 | 语气自然；可完整回答当前一问 | 正常门诊 |
| 有所保留 | 短句、含糊、少主动补充；可用「还行」「基本」 | 在观望 |
| 有点抵触 | 短句；可带委屈/轻声辩解；不骂人；少给新信息 | 被惹恼了、在防备 |
| 不太想聊 | 极短；可回避；不展开病情 | 想结束 |
| 放松了一些 | 可出现「那我说实话」；允许多交代一点细节 | 松口了 |

**注意：** 表里每一行同时约束 **信息量、句式、语气词**，不是只写「短一点」。

### 4.2 按人设叠加「声音人格」（仍是文字侧）

TTS 音色可以所有人共用一条；**差异靠文案习惯**：

| 人 | 文字上的讲话习惯（提示词可写死倾向） |
|----|--------------------------------------|
| 李建国 | 客气、司机口吻；含糊时爱用「基本」「可能记错了」 |
| 王阿姨 | 偏慢；听不清就 **请求重复**；可提女儿 |
| 张大爷 | 把关键问题 **再问一遍**（退出、疗效） |
| 张大妈 | 焦虑时连问钱/跑几趟；被敷衍则突然收束、想走 |

→ 同一 stance「抵触」，四人说出来的 **句子模样不同** —— 这才是可演示的情绪差异。

### 4.3 提示词里建议写清的字段（设计清单）

每一轮组装给 SP 生成的指令，至少包含：

1. **当前心情标签**（有所保留 / 抵触…）  
2. **讲话方式**（上表）  
3. **本轮允许的事实**（披露深度裁剪）  
4. **人设口吻一句**（司机客气 / 请说慢点…）  
5. **禁止项**（不骂人、不编事实、不一次倒干净）  

可选增强（仍属文字，不是 TTS）：

- 抵触时少用完整长句，允许多用省略、重复「记不清」  
- 放松时允许出现转折：「那我说实话……」  
- 王阿姨跟不上时：优先生成「请您再说一遍」类请求，而不是继续听不懂硬答  

### 4.4 和思考逻辑的关系

```text
03 思考引擎：算出 stance + 允许事实
       ↓
06 表达层：把 stance 译成「讲话方式提示词」
       ↓
生成文字（学员已能感到情绪）
       ↓
（可选）TTS 朗读同一段文字
```

**不要** 指望：思考引擎算了「angry」→ TTS 一读就愤怒。  
**要做** 的是：思考引擎算了「defensive」→ 提示词逼出防备句式 → 文字本身有情绪。

## 五、播报层 · TTS 怎么定位（技术边界说清）

### 5.1 现状

| 项目 | 说明 |
|------|------|
| 链路 | 文字由 Agnes/病人 Agent 生成 → MiniMax TTS 朗读 |
| 参数 | 可传 `emotion` 等；效果不稳定，失败则降级重试/静音 |
| 产品态度 | **可关**；纯文字必须能完整练、完整答辩 |

### 5.2 TTS 做得到 / 做不到

| 做得到（有限） | 做不到（不要当设计依赖） |
|----------------|--------------------------|
| 把字读出来，降低阅读负担 | 稳定演绎怒/喜/哀如真人演员 |
| 统一音色、语速配置 | 靠声线区分张大爷/王阿姨情绪层次 |
| 软失败不影响对话主链路 | 作为「有没有情绪」的验收标准 |

若未来要加强听感，优先顺序建议：

1. **先把表达层提示词做稳**（本周可做）  
2. 再试不同 `voice_id` / 语速做「人设音色」粗分（可选）  
3. 最后才考虑真情感 TTS / 实时语音（后置，不挡答辩）

### 5.3 学员端交互原则

| 模式 | 心情标签 | 语音 |
|------|----------|------|
| 练习 | 可显示「有点抵触」等 | 默认可开，可关 |
| 考核 | **隐藏** 细心情 | 建议关，减干扰 |
| 答辩演示 | 可闪一下标签 | **建议纯文字**，避余额/延迟 |

现在是一问一答；真「打断说话」不做本期重点。

## 六、对外怎么讲（避免被问倒）

**别人问：「你们情绪怎么做的？用 TTS 情绪参数吗？」**

> 主路径不是 TTS。我们先用规则算受试者状态，再在提示词里规定讲话方式——短、含糊、请重复、那我说实话——让文字本身带情绪。TTS 只是把字读出来，读不出来也不影响训练。

**别人问：「那语音还有必要吗？」**

> 有，但是增强项：沉浸、无障碍友好。验收和答辩以 **对话 + 评分** 为准；语音可关。

## 七、落点与验收

### 7.1 该改的技术点

| 优先级 | 事项 |
|--------|------|
| P0 | 强化 `speak_style` / 表达包写入生成 prompt（按 stance + 人设） |
| P0 | 练习显示心情；考核隐藏 |
| P0 | TTS 失败静默降级，对话不中断 |
| P1 | 四人各写一段「口吻提示」进病例 |
| P2 | 人设分音色 / 真情感 TTS |
| P3 | 实时语音打断 |

### 7.2 验收（不靠「听出哭腔」）

- [ ] **关喇叭**：责备→防备句式；安抚→松口句式，学员读得出差别  
- [ ] **开喇叭失败**：仍能继续打字练完  
- [ ] 王阿姨「请说慢点」类表达稳定出现（跟不上时）  
- [ ] 考核过程不强调心情 HUD  
- [ ] 答辩主线仍是对话与评分，不依赖语音演示成功
