# 调研笔记：会追问 / 可控的医疗对话 AI

> 目的：回答王铮老师「问题引擎怎么做」——先看业界怎么拆，再落到我们知情同意 SP。  
> 日期：2026-08-31

---

## 1. 共性结论（可直接用）

几乎所有「像样的」医疗对话训练系统都 **不** 把「整段对话」交给单一 LLM 自由发挥，而是拆成：

```text
学员一句话
    → 意图 / 动作分类（State Tracker）
    → 按状态取「可披露事实」（Memory / Case Bank）
    → 病人口吻生成（Patient Generator）
    → （可选）结束后轨迹评分（Evaluation Agent）
```

这与导师强调的一致：**成败关键是「病人想之所想」的可控逻辑，不是皮肤有多真。**

---

## 2. 代表方案

### 2.1 State Aware Patient Simulator（SAPS）

- 论文：[Automatic Interactive Evaluation… State Aware Patient Simulator](https://arxiv.org/html/2403.08495v3)
- 三件套：**State Tracker**（把医生每轮话分到约 10 类动作）+ **Memory Bank**（按类取相关病历片段）+ **Response Generator**
- 启发：我们的「问题引擎」第一步应是 **研究者话术 → 沟通阶段/意图标签**，而不是直接让 SP 随意答。

### 2.2 EasyMED / MedEasy（多 Agent 标准化病人）

- 代码：[FreedomIntelligence/EasyMED](https://github.com/FreedomIntelligence/EasyMED)
- 论文：[MedEasy: Designing AI Standardized Patients…](https://arxiv.org/html/2606.17512v2)
- 拆分：**Auxiliary Agent（意图）** → **Patient Agent（病例接地回复）** → **Evaluation Agent（轨迹评价）**
- 启发：  
  - 意图识别与病人说话解耦 → 稳定性更好  
  - 评价看「整条轨迹」，不只看最后一句  
  - 我们评分引擎已有规则+LLM，缺的是 **过程态阶段** 与 **开练导览**

### 2.3 Agent Hospital · Patient Agent

- 简介：[Patient Agent · Agent_Hospital](https://deepwiki.com/wisdom-pan/Agent_Hospital/4.2-patient-agent)
- 画像 + 病历锁死；主诉优先；按问诊块回答；角色前缀区分对象
- 启发：系统提示里明确「未问不泄」「主诉优先」——我们已有类似 grounding，可加强 **阶段门控**

---

## 3. 映射到 AISP（知情同意 / 随访）

| 业界组件 | AISP 落地建议 |
|----------|----------------|
| State Tracker | `intent_router`：把学员话映射到沟通阶段（见 02） |
| Memory Bank | 现有 case JSON + `dialogue_hints`；按阶段过滤可说事实 |
| Patient Generator | 现有 `patient_agent.py` + 阶段约束 system prompt |
| Evaluation | 现有 `scoring_engine`；增加「阶段完成度」过程指标 |
| 导览 | 开练前展示 8～12 个沟通点（学员端缺口 P0） |

---

## 4. 不建议照搬的

- 全套多 Agent 云端编排（成本高、延迟大）— MVP 可用 **规则意图 + 单次 LLM 回复**  
- 过度依赖语音情绪模型 — 先用 **文本情绪标签 + Live2D 表情**  
- 追求与真人 SP 完全一致 — 教学目标是「清单覆盖 + 红线不踩」

---

## 5. 下一步（实现顺序）

1. 冻结阶段表与意图表（文档 01 / 02）  
2. 学员端先做「看得见的阶段进度」（可先用启发式关键词，不调 LLM）  
3. 服务端再加 `intent_router` 写回 `session_meta`  
4. 再改 patient prompt 按阶段披露
