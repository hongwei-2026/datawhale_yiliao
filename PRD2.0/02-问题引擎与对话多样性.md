# 问题引擎与对话多样性（PRD 2.0）

## 1. 要解决的问题

现状：每次新建对话路径偏固定，SP 开场与追问同质化。  
目标：在 **事实锁死** 前提下，引入可控随机与状态推进。

---

## 2. 总体架构（推荐落地）

```text
┌─────────────┐     ┌──────────────────┐     ┌─────────────────┐
│ 学员发言     │────▶│ Intent Router    │────▶│ Session State   │
│              │     │ (规则+可选LLM)    │     │ stages[]        │
└─────────────┘     └────────┬─────────┘     └────────┬────────┘
                             │                         │
                             ▼                         ▼
                    ┌──────────────────┐     ┌─────────────────┐
                    │ Case Memory Gate │────▶│ Patient Agent   │
                    │ 本阶段可披露事实  │     │ 生成口语回复     │
                    └──────────────────┘     └─────────────────┘
```

**MVP 简化：** Intent Router 先用关键词/正则；不准再等「完美 LLM 分类」才做学员端进度条。

---

## 3. 意图表（知情同意 · 初版）

| intent_id | 含义 | 触发示例（启发式） | 推进阶段 |
|-----------|------|-------------------|----------|
| `greet_frame` | 说明谈话框架/ICF | 知情同意书、伦理、批准 | 1 |
| `purpose` | 试验目的 | 目的、为什么做、研究什么 | 2 |
| `procedure` | 流程安排 | 抽血、来几次、访视 | 3 |
| `risk` | 风险不便 | 风险、副作用、不适 | 4 |
| `benefit` | 获益不确定 | 有效、获益、安慰剂 | 5 |
| `voluntariness` | 自愿退出 | 退出、不参加、自愿 | 6 |
| `compensation` | 补偿损害 | 补偿、医药费、交通 | 7 |
| `qa_close` | 答疑收尾 | 还有问题吗、电话、副本 | 8 |
| `pressure` | 施压/利诱（负向） | 必须签、不签没药 | 红线监控 |
| `overpromise` | 过度承诺（负向） | 一定治好、绝对安全 | 红线监控 |
| `other` | 未识别 | — | 不推进 |

随访意图另表：`missed_dose` / `ae_symptom` / `concomitant` / `pill_count` / `diary` / `safety_contact` / `blame` 等。

## 4. 会话状态（写入 DB）

`training_session.meta_json` 扩展：

```json
{
  "session_mode": "practice",
  "study_mode": "reference",
  "opening_id": "op_family",
  "dialogue_engine": {
    "version": "2.0-draft",
    "current_stage": 3,
    "stages": [
      { "id": 1, "key": "greet_frame", "status": "done", "hit_at_turn": 2 },
      { "id": 2, "key": "purpose", "status": "done", "hit_at_turn": 4 },
      { "id": 3, "key": "procedure", "status": "active", "hit_at_turn": null },
      { "id": 4, "key": "risk", "status": "todo" }
    ],
    "intents_log": [
      { "turn": 4, "intent": "purpose", "confidence": 0.8, "source": "rule" }
    ]
  }
}
```

前端用同一结构渲染 **阶段进度条**；未完成练习摘要直接读 `current_stage` + 已完成数。

## 5. 多样性策略

| 策略 | 说明 | MVP |
|------|------|-----|
| 开场池 | 会话创建时加权随机 | ✅ |
| 卡点顺序微扰 | 病人主动关切的顺序打乱（仍不泄未授权事实） | ✅ 轻量 |
| 追问强度 | 同一意图下 2～3 种追问模板 | ✅ |
| 完全自由 LLM 规划下一问 | 成本高、难评 | ❌ 后置 |

**禁止：** 为多样性编造病例外检查结果、诊断、用药。

---

## 6. API 草案（实现时）

- `POST /api/sessions` — 返回 `opening` + `stages` 初始态  
- `POST /api/sessions/{id}/turns` — 响应增加 `intent`, `stages`  
- `GET /api/sessions/{id}` — 带上 `dialogue_engine` 供恢复  

前端乐观更新阶段；以服务端为准。

---

## 7. 验收

- [ ] 新会话开场来自 opening_pool，且 meta 有 `opening_id`  
- [ ] 学员提到「副作用」后，阶段「风险」标记完成（启发式即可）  
- [ ] 刷新/重进后阶段进度与对话一并恢复  
- [ ] 负向意图触发时，不阻止对话，但结束评分仍抓红线
