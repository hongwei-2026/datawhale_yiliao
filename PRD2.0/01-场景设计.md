# 场景设计（PRD 2.0）

## 1. 目标

让每次练习 **更接近真实门诊沟通**：有情绪、有卡点、有不同开场；但事实仍锁在病例 JSON 内。

「系统功能」展示页本迭代不做；场景能力落在 **模拟对话 + 病例配置**。

---

## 2. 场景类型（当前产品）

| scene_key | 标签 | 典型 Persona | 学员目标 |
|-----------|------|--------------|----------|
| `informed_consent` | 知情同意沟通 | 张大爷 / 王阿姨等 | 讲清目的、风险、自愿退出等 L1 点 |
| `follow_up` / `adherence` | 随访依从性 | 李建国（HTN W4） | 平和追问漏服/AE/合并用药，不责备 |

后续扩场景必须带：**阶段表、卡点、开场池、情绪曲线**（本文件模板）。

---

    "opening_pool": [

      { "id": "op_time", "weight": 1, "line": "我赶着回去看孙子，能不能长话短说？" },
      { "id": "op_fear", "weight": 1, "line": "听说临床试验都是小白鼠，是不是真的？" }
    ],
    "pressure_points": [
      {
        "id": "pp_efficacy",

        "good_researcher_move": "说明可能获益与可能无效，不保证疗效",
        "bad_researcher_move": "包治 / 绝对有效"
      },
      {
        "id": "pp_exit",
        "trigger_intent": ["voluntariness"],
        "patient_worry": "签了就不能反悔、退出影响看病",
        "good_researcher_move": "随时可退出且不受歧视",
        "bad_researcher_move": "暗示不签就没药 / 退出影响待遇"
      }
    ],

## 4. 情绪与「语音情绪」（MVP）

| 层级 | MVP | 后置 |
|------|-----|------|
| 文本语气 | system prompt + 情绪标签 | — |
| Live2D 表情 | thinking / speaking / sad | 更细粒度 |
| TTS 情绪参数 | MiniMax emotion 字段粗调 | 按句切换 |
| 真口型 MuseTalk | 不做本迭代 | GPU 云 |

## 5. 知情同意 · 推荐沟通阶段（给学员看的「导览」）

与评分项对齐，**开练前必须可见**（解决「没有 12 个沟通点」的批评）：

1. **破冰与身份** — 说明谈话目的、伦理批准材料（IC-P01/P02）  
2. **试验目的** — 为什么做、解决什么问题（IC-C01）  
3. **流程安排** — 来几次、抽血服药等（IC-C02）  
4. **风险与不便** — 主要风险，不淡化（IC-C04，红线 IC-X03）  
5. **获益不确定** — 可能无效（IC-C05，红线 IC-X02）  
6. **自愿与退出** — 可拒绝、可随时退出（IC-C09/P05，红线 IC-X01/X04）  
7. **补偿与损害处理** — 花费/补偿/损害原则（IC-C07/C08）  
8. **答疑与收尾** — 留时间提问、联系方式、副本（IC-P04/C13/P10）

随访场景另表（漏服 → AE → 合并用药 → 药盒 → 安全联系），见病例 `CASE-HTN-PH3-W4-001`。

---

## 6. 验收标准（设计层）

- [ ] 同一病例连续开 3 次新会话，开场不全相同（有 opening_pool）  
- [ ] 学员在开练前能看到本场景沟通阶段列表  
- [ ] 卡点被踩中时，病人反应与 `emotion_rules` 一致（人工抽检）  
- [ ] 不出现病例外医学事实（现有 grounding 继续生效）
